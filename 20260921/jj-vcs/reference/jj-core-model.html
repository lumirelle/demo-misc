The jj core model & command map

The compressed essence of Lesson 1 — keep this within reach.

The model in one line

The working copy is itself a commit (marked @), and every command snapshots your edits into it automatically. There is no index, no staging area, and no "dirty tree".

Log symbols

Symbol 
@   working-copy commit
○   ordinary (mutable) commit
◆   immutable commit (the root)
Two identifiers 
change ID  stable (zuryntwn)
commit ID  content hash (4fa33b2b)

A change ID survives rewriting; a commit ID changes whenever its content changes. Rewriting re-uses the change ID with a new commit ID.

Command map (Git → jj)

Git 
git init
git status
git add .
git commit -m "msg"
git log
git checkout -b foo
jj 
jj git init
jj st
(automatic)
jj describe -m "msg"
jj log
jj new   (bookmarks come later)

The daily loop

jj new                       # start a fresh commit on top
# ... edit files ...
jj st                        # changes are already recorded
jj diff                      # see them
jj describe -m "message"     # name the commit
jj log                       # read history, top = newest

One-time identity setup

jj config set --user user.name  "Your Name"
jj config set --user user.email "you@example.com"

jj uses its own [user] config, not Git's user.name/user.email. Skip this and commits get an empty identity that can't be pushed.
