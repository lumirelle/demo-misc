Jujutsu · Lesson 0002

Amend, reword, undo

Fixing mistakes is a single command each — because in jj, every commit is just as editable as the latest one.

In Git, "oops, fix that" is a ceremony: git commit --amend only reaches the last commit, and touching anything older means git rebase -i and hoping nothing breaks. jj was built so that rewriting is a normal, first-class act — on any commit, not just the tip.

The one idea

Every commit in jj is mutable (except the root and remote bookmarks). When you rewrite a commit, jj does something Git never does for you: it automatically rebases all of that commit's descendants onto the new version. You change one commit in the middle of history; jj re-stacks everything on top for you.

That's why the two identifiers from Lesson 1 matter: a change ID survives rewriting, while its commit ID changes. "Amending" here really means "same change, new content."

The three verbs you're about to learn

Amend → jj squash  ·  Reword → jj describe -r  ·  Undo → jj undo. Note there is no jj amend command — jj's answer to git commit --amend is jj squash.

Do it now

Build a tiny three-commit history first. (Change IDs and hashes on your machine will differ.)

jj git init fix-demo
cd fix-demo
echo "a" > a.txt
jj describe -m "add a.txt"
jj new
echo "b" > b.txt
jj describe -m "add b.txt"
jj new

Your graph should look like this — top is newest:

@  nzzqmttw  (empty) (no description set)
○  lowxwzku  add b.txt
○  puwrzzkk  add a.txt
◆  zzzzzzzz  root()
  1. Reword the oldest commit. The @-- means "grandparent of the working copy" — the add a.txt commit. 
    jj describe -r @-- -m "add a.txt (fixed typo)"
    Rebased 2 descendant commits.
Working copy  (@) now at: nzzqmttw a20bbd78 (empty) (no description set)
Parent commit (@-)      : lowxwzku f69b8243 add b.txt

    Watch the first line: "Rebased 2 descendant commits." You rewrote the bottom commit, and jj automatically re-stacked the other two on top. In Git you'd be deep in an interactive rebase right now.

  2. Amend: add more work into the previous commit. You're sitting on an empty @ above add b.txt. Change b.txt and fold the change back into its commit. 
    echo "extra line" >> b.txt
jj st
    Working copy changes:
M b.txt
Working copy  (@) : nzzqmttw 6b68b702 (no description set)
Parent commit (@-): lowxwzku b8c4e2b5 add b.txt

    Now the amend itself — one word:

    jj squash
    Working copy  (@) now at: mwqlvlkw e4976c08 (empty) (no description set)
Parent commit (@-)      : lowxwzku 93494c04 add b.txt

    jj squash with no arguments folds the working-copy commit into its parent — exactly git commit --amend. Notice the parent's change ID stayed lowxwzku while its commit ID changed (b8c4e2b5 → 93494c04). Same change, new content.

  3. Undo it. 
    jj undo
    Undid operation: 3cbe57ec70fd (…) squash commits into f69b8243b78c…
Restored to operation: 178f2445b926 (…) snapshot working copy
Working copy  (@) now at: nzzqmttw 9793c863 (no description set)
Parent commit (@-)      : lowxwzku f69b8243 add b.txt

    jj undo rewinds the last operation. It's powered by the operation log, which replaces Git's reflog — but unlike the reflog, it's a first-class, navigable thing you can jj op log through and jj redo forward.

What you just did

You rewrote a commit in the middle of history, had its descendants re-stacked automatically, folded new work into an existing commit, and undid it all — three things that in Git require rebase -i, --amend, and squinting at the reflog. In jj each is one short command, and none of them can leave you stranded, because jj undo is always one keystroke away.

When to use which

Editing the commit you're on: just edit files and jj describe. Folding your current work into the previous commit: jj squash. Changing an older commit's message: jj describe -r <rev>. (Editing an older commit's content is next lesson.)
