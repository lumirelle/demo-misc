Jujutsu · Lesson 0004

Move changes between commits

"This change belongs in an earlier commit" — fix it in one command, no cherry-pick, no rebase -i.

You make a commit, then realize one of its files actually belongs in the commit below it. In Git that's git rebase -i with fixup markers or a manual cherry-pick dance. In jj, changes are first-class movable objects, and jj squash moves them anywhere.

The one idea

Lesson 2 taught jj squash with no arguments — fold the working copy into its parent. The same command, given --from and --into, moves changes between any two commits:

jj squash --from <source> --into <destination>          # move everything
jj squash --from <source> --into <destination> <path>   # move one file's changes

Add a path and only that file's changes move; the source keeps the rest. Omit the path and everything moves — and if that empties the source commit, jj abandons it and asks you to combine the two commit messages.

Mind the off-by-one

In a stack @ → B → A → root, the levels are @- = B, @-- = A, and @--- = the root. It's easy to aim one level too deep and hit the immutable root — count your dashes.

Do it now

Build a stack where the second commit accidentally contains two files, and one of them belongs in the first commit. (Change IDs on your machine will differ.)

jj git init surgery-demo
cd surgery-demo
echo "a" > a.txt
jj describe -m "add a.txt"
jj new
echo "b" > b.txt
echo "note" > notes.txt
jj describe -m "add b.txt and notes"
jj new

Top-to-bottom:

@  ulosmsyw  (empty) (no description set)
○  wtytlksy  add b.txt and notes
○  tykzqmxx  add a.txt
◆  zzzzzzzz  root()

Oops — b.txt really belongs with a.txt. Move it down.

  1. Move one file's change into the earlier commit. @- is the b.txt and notes commit (source); @-- is add a.txt (destination). 
    jj squash --from @- --into @-- b.txt
    Rebased 2 descendant commits.
Working copy  (@) now at: vsosyoll 75af21fc (empty) (no description set)
Parent commit (@-)      : xuonrmwm 8412859d add b.txt and notes

    Confirm it worked:

    jj diff -r @--
    Added regular file a.txt:
        1: a
Added regular file b.txt:     ← now part of "add a.txt"
        1: b

    And the source commit keeps the rest — notes.txt stayed behind:

    jj diff -r @-
    Added regular file notes.txt:
        1: note

    One command, no editor, no conflict. That's the whole lesson.

  2. Or move everything (and let the source disappear). Undo, then try it without the path: 
    jj undo
jj squash --from @- --into @--

    This moves all of @-'s changes into @--. The source is now empty, so jj abandons it and opens your editor to combine the two commit messages — the only time an editor appears in this flow.

What you just did

You relocated a file's changes from one commit into an earlier one — the classic "I committed this in the wrong place" fix. By path, it's surgical and silent; wholesale, it folds the commit and merges the messages. Both are one command each, where Git needs an interactive rebase or a cherry-pick with a reset to follow.

The reverse direction

What about "this commit does too much — separate it"? That's jj split (jj split -i is the git add -p equivalent). Next lesson.
